# Android 客户端出包与升级（0.1.0）

记录自托管签名 APK 的构建、校验、分发与升级流程，以及 M4 打磨（R8 / 资源收缩 / Baseline Profile）
的落地方式和验收结果。

## 1. 版本与产物

| 项 | 值 |
| --- | --- |
| 版本 | `versionCode`（出包前自增，当前 8） / `versionName 0.1.0`——只改 `app/build.gradle.kts` 一处 |
| SDK | minSdk 30、compile/target 36 |
| 产物 | `release/fakenews-comics-<version>.apk`（release 3.5MB 上下，单 dex；debug 约 46MB） |
| SHA-256 | 自行生成：`sha256sum release/*.apk > release/SHA256SUMS.txt`（不入库，随发布渠道分发） |
| ABI | arm64-v8a / armeabi-v7a / x86 / x86_64（只有 androidx.graphics.path 一个 .so） |
| 签名 | 自签证书 `CN=Fakenews Comics, OU=Self-hosted, O=Fakenews, C=CN`，SHA-256 `f1b3d858…d71d9c2` |

release 开了 R8 混淆 + 资源收缩，debug 包 46MB、release 包 3.5MB，差异主要来自未裁剪的 Compose/Coil。

## 2. 出包步骤

签名材料在仓库外，口令不进仓库：

- 密钥：`C:\Users\<you>\.android\fakenews-release.jks`（alias `fakenews`，RSA 4096，有效期 10000 天，PKCS12）
- 口令与路径：`~/.gradle/gradle.properties` 里的四个属性，模板见 `key.properties.example`

```bash
export JAVA_HOME=/path/to/jdk-17            # 需要 JDK 17
gradle :app:assembleRelease                 # 或用你本机 Gradle 的绝对路径

# 一定要验签：四项属性缺任意一项时构建不会失败，只是不签名
"$ANDROID_HOME/build-tools/<build-tools 版本>/apksigner" verify \
  app/build/outputs/apk/release/app-release.apk
"$ANDROID_HOME/build-tools/<build-tools 版本>/apksigner" verify --print-certs \
  app/build/outputs/apk/release/app-release.apk

mkdir -p release
cp app/build/outputs/apk/release/app-release.apk "release/fakenews-comics-<version>.apk"
cd release && sha256sum "fakenews-comics-<version>.apk" > SHA256SUMS.txt
```

密钥丢失意味着**后续版本无法覆盖升级**（只能卸载重装），务必连同 `~/.gradle/gradle.properties`
一起备份。仓库只保留 `key.properties.example`，`.gitignore` 已排除 `*.jks` / `*.keystore` / `keystore/`。

## 3. R8 与资源收缩

`app/build.gradle.kts` 里 release 打开 `isMinifyEnabled` + `isShrinkResources`，
规则集中在 `app/proguard-rules.pro`：

- kotlinx.serialization：保留 `@Serializable` 对应的 `Companion` / `$serializer` / `INSTANCE`
- Retrofit：保留 `FakenewsApi` 接口与 `retrofit2.Call` / `retrofit2.Response` / `Continuation`
- `-dontwarn com.google.errorprone.annotations.Immutable`（Tink 传递依赖，缺了 R8 会直接失败）

判据不是「能编译」，而是 release 包上这些链路都还能跑：JSON 反序列化（书架 509 部 / 详情 / 记录）、
Coil 图片解码、Hilt 注入、DataStore 配置读写 —— 见第 6 节回归结果。

## 4. Baseline Profile

- 采集模块：`android/baselineprofile`（`com.android.test`，`targetProjectPath = ":app"`）
- 采集用例：`BaselineProfileGenerator.generate`，覆盖启动 → 连接服务器 → 书架 → 下滚两屏 → 详情 →
  阅读器翻两页
- 规则文件：`app/src/release/baselineProfiles/baseline-prof.txt`（25,346 条）

### 4.1 重新采集

```bash
# 模拟器需先唤醒解锁，并保持常亮，否则目标进程不出帧
adb shell input keyevent KEYCODE_WAKEUP && adb shell wm dismiss-keyguard
adb shell svc power stayon true

cd android
$GRADLE :baselineprofile:connectedBenchmarkAndroidTest
# 产物
# baselineprofile/build/outputs/connected_android_test_additional_output/benchmark/connected/<设备>/
#   BaselineProfileGenerator_generate-baseline-prof.txt
cp "<上面的文件>" app/src/release/baselineProfiles/baseline-prof.txt
$GRADLE :app:assembleRelease
```

验证是否真的打进包：

```bash
unzip -l app/build/outputs/apk/release/app-release.apk | grep dexopt   # assets/dexopt/baseline.prof
# 装上后首启会在 App 私有目录写入安装后的 profile
adb root && adb shell ls -la /data/misc/profiles/cur/0/com.fakenews.comics/   # primary.prof
adb shell cmd package compile -m speed-profile -f com.fakenews.comics          # 可选：立刻验证被接受
```

### 4.2 踩过的坑

- **`src/release/baseline-prof.txt` 不生效**。AGP 8.x 对 app 只认 `src/<variant>/baselineProfiles/baseline-prof.txt`
  （或 `src/main/baseline-prof.txt`）；放错位置时 `mergeReleaseArtProfile` 照常成功，但合并结果里只有依赖库的规则。
  判断方法：看 `app/build/intermediates/merged_art_profile/release/mergeReleaseArtProfile/baseline-prof.txt`
  里有没有 `com/fakenews` 开头的条目。
- **必须在未混淆的变体上采集**。直接用 release（R8 后）跑，规则全是 `LA/a;` 这类混淆名；换一次构建
  mapping 就变，R8 重写阶段匹配不上会整段丢弃。为此 `app` 增加了 `benchmark` 构建类型
  （`initWith(release)` + `isMinifyEnabled = false` + debug 签名），`baselineprofile` 模块的
  `benchmark` 变体自动匹配它。生成的未混淆规则在 release 构建时由 R8 重写成混淆名
  （`combined_art_profile` 里能查到 `a2/x` 等对应条目）。
- **API 36 上 `startActivityAndWait()` 不可用**：报 `Unable to confirm activity launch completion []`，
  因为 `dumpsys gfxinfo <pkg> framestats` 的帧等待拿不到新帧记录（设备锁屏/休眠时更明显）。
  采集用例因此改成 `am start -W` 启动 —— 采 profile 只关心「进程跑起来并交互过」，不关心启动耗时。
- **`pm dump-profiles` 输出变了**：benchmark 1.3.3 期待 `Profile saved to '...'`，API 36 返回
  `Waiting for app processes to flush profiles...`，于是测试失败但 `/data/misc/profman/*.prof.txt`
  其实已经生成。升到 `androidx.benchmark:benchmark-macro-junit4:1.5.0` 后正常。
- 模拟器是 userdebug，必须带 `androidx.benchmark.suppressErrors=EMULATOR,DEBUGGABLE`
  （已在 `baselineprofile/build.gradle.kts` 的 `testInstrumentationRunnerArguments` 里固定）。
- 目标进程需要 `<profileable android:shell="true"/>`，已在 `AndroidManifest.xml` 里声明；
  它只放开 shell 采样，不影响普通运行。

## 6. 升级与安装说明

- **覆盖安装**：新包必须用同一把 keystore 签名，否则 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
  升级只替换代码，本地配置（服务器地址、阅读偏好、Cookie 会话）保留。
- **卸载重装**：本地配置会被清掉，需要重新填服务器地址；书架/进度/收藏/记录都在服务端，不会有数据损失。
- **安装渠道**：直接分发 APK（`adb install -r` 或文件管理器点开安装）。首次安装需允许「安装未知来源应用」。
- **兼容性**：minSdk 30（Android 11）起；横屏、折叠屏、分屏、挖孔/曲面屏在 M3 已适配。
- **回滚**：保留上一版 APK 即可覆盖安装旧版本（versionCode 更小的包不能直接降级，需要 `adb install -r -d`
  或先卸载）。
